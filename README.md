# Linglass-Pro

在 [Linglass](https://chromewebstore.google.com/detail/nhncklckpmkkhjcijjgfcgclfpbbkcba)（YouTube 上的双语字幕扩展）之上做**增量改造**的浏览器扩展：官方代码一个字节都不改，构建时把它叠加成一个新扩展。

三个主要功能：

- **桌面字幕浮窗**（默认关闭，需要时自己开）—— 把官方渲染的双语字幕投送到**系统级画中画窗口**。浏览器最小化、切到别的应用之后，字幕依然留在桌面上，句内进度继续走，还能换句、暂停、调倍速。
- **学习面板** —— 页内侧栏里的整条字幕轨：实时双语字幕、当前句高亮、逐句点击跳转，以及导出中日对照 Markdown 与双语 SRT。
- **字幕句内断句** —— 按日语「文节」切开原文行，便于跟读与朗读停顿。

## 桌面字幕浮窗（默认关闭）

窗口长这样 —— 字幕区是「上一句 / 当前句 / 下一句」三段（每段上面原文、双语开着时下面跟译文），原文可带注音与文节分隔符，底部是句内进度条和控制栏；控制栏右端的 `Aa` 会把整条换成样式条：

![桌面字幕浮窗示意](docs/images/pip.svg)

- **默认关闭**：画面里那层 Linglass 字幕本来就够用（还能点词查词），所以没表过态的浏览器里不会自动多弹一扇系统窗口；想看桌面浮窗就点控制栏按钮或 Linglass 设置面板里的开关。**开了之后就一直是开着的**：点浮窗自己的 `×`、切到别的应用、刷新页面、换视频，窗口都会自己回来 —— 能真正关掉它的只有那两个开关。
- **「只留一个字幕面」是默认值，不是隐藏**：我们**不会**在浮窗开着时把画面里的官方字幕藏起来。实测那省不了资源（官方字幕组件的 JS 照跑，只是不画），却会让画面里的点词查词没法用 —— 省下来的开销在下面「工作原理」里说。
- **歌词式句内进度**：句级时间轴来自自建的字幕轨道，句内线性插值；由 PiP 窗口自己的 `requestAnimationFrame` 驱动，另加 1s 心跳兜底，所以宿主窗口最小化时进度照走。
- **播放控制栏**：上一句 / 播放暂停 / 下一句（播到句中超过 1s 时先回到本句开头）/ 倍速档位（0.75× – 2×）。
- **开窗时贴合内容，之后大小随你拖**：开窗尺寸按当时的样式算 —— 就是「字幕两行 + 控制栏」那点高度，上下不留大块黑边（不是写死的 1000×264）；之后**拖多大、拖多小都不动字号**：字号只跟 `Aa` 样式条里的档位走，窗口拖大不会把字放大。
- **观感与 Linglass 一致，但浮窗自己可调**：排版规则照搬官方「外观」（四套预设、字号比例、颜色、底板、描边），**首次打开时**拷一份官方当前设置当初始值；之后在控制栏的 `Aa` 样式条上直接调字号（50–150%）/ 预设 / 颜色 / 双语，**改完就落盘**，`↺` 把官方当前的设置重新拷回来。学习语言 / 母语仍然跟随官方（换了语言，字面与 CJK 字号比例要跟着换）。原文行的注音（`<ruby>/<rt>`）也跟随官方 —— 官方开着就渲染注音，官方关着一个字符都不变。
- **能看上下文**：字幕区是「上一句 / 当前句 / 下一句」三段，上下文行小一号（0.8×）、整段淡到 40%，**只有正在播的那一句是不透明的**。样式条上的 `≡` 循环切换档位 —— `≡0` 只看当前句、`≡1` 加上下一句（默认）、`≡2` 上下都给，档位落盘记住。
- **换句像滚轮**：换句时三段整列推进一格（前进从下方推入、后退从上方推入，260ms；系统开了「减少动态效果」就不动）。改颜色 / 改字号这类外观变化不会触发它。
- **上下文行点得动**：鼠标移到上下两条会变亮，点它 = **跳到那一句的开头接着播**（与控制栏那两个「上一句 / 下一句」按钮不同：那两个在句内超过 1s 时会先回到本句开头）。
  注意：**「下一句」通常只有原文**。译文是官方在播到那一句时才产生的，官方缓存里只有原文；所以除了「当前句」和「刚播过的上一句」，其他行拿不到译文（重看同一个视频时会越攒越多）。这是官方数据的限制，不是渲染漏了。

## 学习面板（常驻，两种挂载形态）

![学习面板的两种挂载形态](docs/images/panel.svg)

- **watch 页**：面板插进 YouTube 自己的推荐列（`#columns #secondary` 的第一个子节点），宽度与位置由 YouTube 计算 —— 因此**不遮挡任何东西**。
- **其它页面**（首页 / 搜索页没有那一列）：退回「右侧悬浮 + 页面让位」，让位规则是实测出来的（见 `tools/probe.mjs`）；那种形态下面板会收窄页面，并在视频全屏时自动收起。
- 宽度可拖（300–760px），关闭后记住宽度与开启状态。
- 能力：实时双语字幕、当前句高亮 + 句内扫过填充、逐句列表点击跳转、导出中日对照 Markdown（Obsidian 友好）/ 双语 SRT / 复制到剪贴板。

## 字幕句内断句

在每节之间画一个分隔符，便于跟读与朗读停顿：

```text
私は|昨日|図書館で|日本語の|本を|借りました。|
```

- 分隔符挂在空 `span` 的 CSS `::after` 上 —— **一个字符都不进文本流**（不改写、不删减、不加空格），所以官方的点词查词、拖拽选词，以及我们的轨道记录与导出都不受影响。
- 切分用浏览器内建的 ICU 分词（`05-ja-segment.js`，零依赖）+ 助词 / 活用 / 量词 / 复合词判据。**逐条规则与边界见 [`docs/plans/020-ja-segment-rules.md`](docs/plans/020-ja-segment-rules.md)**，README 只记一条原则：判不准时一律偏向「另起一节」，且整句只有一个文节时不画分隔符。

## 挂在官方设置面板里

上面这些开关出现在 **Linglass 自己的设置面板**（`Linglass-Pro` 分组）里，与「字幕样式」「同步模式」那些行同款观感，而不是页面上的外挂按钮。

## 环境要求

- Node.js 18+（用到 `node:test` 与全局 `fetch`）
- macOS 或 Windows（解包 CRX 走仓库自带的 `tools/zip.mjs`，零依赖，**不需要**系统的 `unzip`）
- Chrome / Arc 或任意 Chromium 116+ 浏览器（桌面字幕浮窗需要 `documentPictureInPicture`）

## 只想装上用（不写代码）

要把扩展装进**别人的浏览器**，对方不需要懂命令行。一条命令产出两个包：

```bash
make package   # → release/Linglass-Pro-<版本>-extension.zip
               #   release/Linglass-Pro-<版本>-installer.zip
```

| 包 | 对方要做什么 | 体积 |
| --- | --- | --- |
| **完整版** `-extension.zip` | 解压 → 在扩展页选中那个文件夹 → 完事。**不用装任何东西、不用联网** | 约 1 MB |
| **安装器版** `-installer.zip` | 先装 [Node.js](https://nodejs.org/zh-cn/download)（LTS）→ 双击 `install-macos.command` / `install-windows.bat` → 等它拉官方基线并构建 | 约 0.1 MB |

两种包最后都剩同样 4 下点击（开发者模式 → 加载已解压的扩展程序 → 选中文件夹 → 完成），那是 Chrome 的安全边界，没有任何脚本能代劳。包里各带一份图文向导（源文件 [`docs/install-guide.html`](docs/install-guide.html)，完整版里叫 `INSTALL.html`）。

文件名里的 `1.12.4.900` 读作「官方基线 1.12.4 + 本项目的第 900 号补丁」：产物版本号的 patch 固定为 `900`（避免和商店更新撞号），所以**只能靠文件名里这段分辨基于哪个官方版本**。

> ⚠️ **完整版包含 Linglass 的官方代码。** 分发它是使用者的选择，风险由分发者承担：公开传播可能招致原作者投诉乃至被 DMCA 下架，建议只在私人范围流传。想发一个「干净」的包就用**安装器版**（只含我们自己的代码，官方基线由对方的电脑在安装那一刻自己去商店取）。
>
> `make package` 打完包会把两个 zip 读回来自检：安装器版混进 `vendor/` 或 `dist/` 直接失败，完整版校验「有没有内嵌一层、`manifest.json` 在不在那一层的根」。无论哪种包，`vendor/` 与 `dist/` 都**不进版本控制**。

### 装好后需要登录（可能用不了 Google 登录）

官方扩展是**登录之后才翻译**的，我们不提供替代方案 —— 所以「没有字幕数据就没有一切」：浮窗与学习面板都依赖它。

- 登录页支持 **Google / Apple 登录**，也支持**邮箱 + 密码注册**。
- **Google 登录在部分网络环境下打不开**（连不上 Google）。遇到这种情况不要反复重试，直接在登录页用**邮箱注册一个自己的账号**即可，装的还是同一个扩展、同样的功能。
- 官方登录页另有一个「不注册继续」的入口，但受限（没有翻译就没有字幕），不建议走。

## 起步（开发）

```bash
make vendor-update   # 从 Chrome 商店下载官方基线到 vendor/，然后构建
make open            # 打开浏览器扩展管理页
```

在 `arc://extensions`（或 `chrome://extensions`）里打开开发者模式，点「加载已解压的扩展程序」，选本项目的 `dist/` 目录。

> `vendor/` 不在版本控制里 —— 那是 Linglass 的专有代码，仓库只把它当只读基线用。第一次使用必须先跑 `make vendor-update`（安装器版打包时这一步由对方的安装程序代劳）。

日常开发用 `make dev`：改完源码自动重建，并让扩展自动重载，不用手点刷新按钮。

## 工作原理

![构建流程](docs/images/architecture.svg)

**只读基线 + 增量叠加。** 官方扩展的打包产物放在 `vendor/` 下，一个字节都不改；我们所有的代码都在 `src/mod/`，构建时叠加到 `dist/`。好处：

- 官方发新版时只需换 `vendor/` 目录（一条命令），`src/mod/` 原样可用；
- `git diff` 里永远不会出现官方代码，一眼能分清哪些是我们写的（`vendor/` 与 `dist/` 都在 `.gitignore` 里）。

构建脚本会顺着官方产物**动态校验**我们依赖的 DOM 契约，官方改版时在构建阶段就告警，而不是等你打开视频发现「字幕不动了」。写出去的 `manifest.json` 还会做一次注入自检（顺序是否如预期、Service Worker 模块有没有被误当内容脚本）。模块之间不传消息，直接共享全局量：

**省资源是设计出来的，不是省出来的。** 三处最容易「看久了变卡」的地方都做了硬约束：

- **共享心跳**：所有模块的「一秒看一眼」（查轨道、补断句标记、对齐浮窗状态……）都挂在
  `00-shared.js` 的**同一个** 1s 定时器上，不是每个模块各挂一个 —— 一个标签页只有一个常驻定时器。
- **每帧不读 DOM**：浮窗与学习面板各有一个 `requestAnimationFrame` 循环，它们每帧都要问
  「现在这一句跟时间轴对上了吗」。这份答案由 MutationObserver + 1s 心跳缓存，rAF 一帧都不碰
  Shadow DOM（早期实现每帧都要查三次、注音行还要克隆一整行 DOM）。
- **落盘有上限**：每个视频最多记 5000 句，`chrome.storage.local` 里最多留 30 个视频 / 30 天。

## `src/mod/` 的文件名约定

数字前缀决定注入顺序。同一扩展的所有内容脚本共享一个 isolated world，因此各模块直接通过 `globalThis.__llgMod*` 互相取用，不走消息传递。

| 文件名 | 作用 |
| --- | --- |
| `00-shared.js` | 共享设施：控制栏按钮工厂、功能注册表、共享心跳、僵尸 DOM 清理 |
| `05-ja-segment.js` | 纯函数：把一句日文切成「文节」，给出断句位置（可在 Node 里直接测） |
| `10-subtitle-track.js` | 字幕轨道记录器：只读官方 Shadow DOM 采样，并用官方缓存的整条原文轨当骨架 |
| `15-ja-break.js` | 字幕句内断句（在 Linglass 的原文字幕行上画分隔符） |
| `30-desktop-subtitles.js` | 桌面字幕浮窗（系统级画中画 + 歌词式进度 + 播放控制栏 + `Aa` 样式条） |
| `40-study-panel.js` | 学习面板（实时字幕、逐句跳转、导出 Markdown / SRT） |
| `50-settings-panel.js` | 把我们的功能挂进 Linglass 自己的设置面板 |
| `dev-reload.dev.js` | 仅在 `make dev` 时注入：唤醒 service worker 检查新构建 |
| `dev-reload.sw.dev.js` | 仅在 `make dev` 时挂到官方 service worker 上（内容脚本没有 `chrome.runtime.reload`） |

## 验证方式

`make test`（`node --test tools/test/*.test.mjs`，零依赖）当前 **123 例全绿**：

```text
$ make test
ℹ tests 123
ℹ pass 123
ℹ fail 0
```

- **契约测试**（`contract.test.mjs`）—— 断言我们对官方产物与 YouTube 平台的所有依赖仍然成立（DOM class、shadowRoot 模式、点击处理器的短路行为、面板的裁剪机制）。选择器从源码里提取，**新增对官方 DOM 的依赖必须登记进来**。
- **冒烟测试**（`smoke.test.mjs`）—— 用 `node:vm` 开沙箱、把 `document` / `chrome` / `MutationObserver` 换成桩件，把 `src/mod/*.js` 原封不动跑起来，覆盖时间轴推导、去重、暂停保护、注音与断句共存、导出格式、常驻语义等。
- **断句与工具链测试**（`ja-segment` / `zip` / `install` / `package`）—— 纯函数单独驱动并断言「切点升序且拼回去等于原文」；zip 往返与 zip64 边界；安装器的候选浏览器表；发布包的结构。后三处的共同点是**错了也不会报错**（双击后什么都不弹 / 解压摊一地 / 加载扩展直接失败），只能靠测试锁住。

浏览器内的视觉与交互（面板滑入、浮窗是否真的留在桌面、MutationObserver 的真实时序）**Node 测不了**，属于人工确认范围；`make probe`（CDP 驱动真实浏览器）可以半自动地跑一部分。

## 已知限制

- 目前**只支持 YouTube**。
- **需要登录**：官方登录后才翻译，Google 登录在部分网络下打不开 —— 见上面「装好后需要登录」一节。
- **整条轨只有原文**：句子与时间戳来自官方缓存的那份原文轨（`10-subtitle-track.js` 的「骨架」一节，只读 `chrome.storage.local`），所以侧栏一打开就是整条；但**译文只可能来自实际播放** —— 官方按块懒翻译、不落盘整条译文轨，所以没看过的句子译文是空的（面板副标题会显示「译文 x/N」）。缓存被 TTL（24h / 最多 50 条）清掉后会自动退回「只记录播放过的句子」。
- **注音只在当前这一句**：官方缓存里本来就不含 `<rt>`，所以浮窗能跟随官方显示注音，而面板逐句列表与导出的 Markdown / SRT 始终是不含注音的纯文本。
- **浮窗高度是刚性的**：字号不跟窗口走，所以窗口拖得比「字幕两行 + 控制栏」还矮时下沿会被切掉；开窗之后再改字号档位也不会自动重算窗口大小 —— 把窗口拖一下即可。
- 面板在**播放页**寄生进 YouTube 的推荐列（不遮挡任何东西）；**其它页面**退回「右侧悬浮 + 页面让位」，会收窄页面并在视频全屏时自动收起。
- 句级时间戳的精度取决于 MutationObserver 的触发时刻（就是字幕切换那一瞬）；官方不暴露内部 cue 时间轴，**词级时间戳拿不到**，词级进度只能用句内线性插值近似。
- **我们自己的轨道也有上限**：每个视频最多记 5000 句（超出丢最旧的），`chrome.storage.local` 里最多留 30 个视频的轨道、30 天（超出自动删）。上限之前是「只增不减」，看多了会把约 10MB 的默认配额写满，表现是「进度莫名其妙记不住了」。
- 运行的是官方商店下发的产物，所以桌面字幕浮窗依赖浏览器的 `documentPictureInPicture`（Chromium 116+，Arc 可用）。
- **「免 Node」和「干净」只能选一个**：安装器版要对方先装一次 Node.js；不依赖 Node 的完整版就得把官方代码一起发出去（见上面 ⚠️）。官方代码总得从某处来，要么从对方机器上取，要么由我们带过去。两条路各自的取舍见 [`docs/plans/023-one-click-installer.md`](docs/plans/023-one-click-installer.md) 与 [`024-download-and-run-package.md`](docs/plans/024-download-and-run-package.md)。
- **官方发新版不会自动同步**：用户要重新双击一次安装文件，再在扩展管理页点一下刷新。

## 开发约定

- **改代码前先读 [`AGENTS.md`](AGENTS.md)**：本仓库要求「一个需求 = 一个 PLAN」，PLAN 必须声明修改范围，越界要停下报告；`vendor/` 与 `dist/` 只读；Bug Fix 必须带回归测试。
- 需求与设计留档在 [`docs/plans/`](docs/plans)，编号连续递增。
- 提交前跑门禁：碰了 `src/mod/**` 就 `make build` + `make test` + `make check`；提交前用 `git diff --stat` 核对改动量级是否与 PLAN 相符。
- 全仓库**零第三方依赖**（`node:test` / `node:vm` / 原生 `fetch` / 手写 CDP WebSocket 与 zip），也不打算为此开例外。
