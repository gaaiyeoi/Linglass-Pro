# linglass-Pro

在 [Linglass](https://chromewebstore.google.com/detail/nhncklckpmkkhjcijjgfcgclfpbbkcba)（YouTube 上的双语字幕扩展）之上做**增量改造**的浏览器扩展。

两个主要功能：

- **桌面字幕浮窗** —— 把官方渲染的双语字幕投送到**系统级画中画窗口**。浏览器最小化、切到别的应用之后，字幕依然留在桌面上，句内进度继续走，还能直接换句、暂停、调倍速。
- **学习面板** —— 页内侧栏里的整条字幕轨：实时双语字幕、当前句高亮、逐句点击跳转，以及导出中日对照 Markdown 与双语 SRT。

## 功能

### 桌面字幕浮窗（默认开启）

窗口长这样 —— 上排是原文（可带注音与文节分隔符），下排是译文，底部是句内进度条与播放控制栏：

![桌面字幕浮窗示意](docs/images/pip.svg)

- **默认开启**：只要用户没有用我们自己的 UI 关掉，它就是开着的。点浮窗自己的 `×`、切到别的应用、刷新页面、换视频，窗口都会自己回来 —— 能真正关掉它的只有控制栏按钮和 Linglass 设置面板里的开关。
- **歌词式句内进度**：句级时间轴来自自建的字幕轨道，句内线性插值；由 PiP 窗口自己的 `requestAnimationFrame` 驱动，另加 1s 心跳兜底，所以宿主窗口最小化时进度照走。
- **播放控制栏**：上一句 / 播放暂停 / 下一句（播到句中超过 1s 时，先回到本句开头）/ 倍速档位（0.75× – 2×）。
- **观感跟随官方**：样式、字号、颜色、是否双语，全部照搬 Linglass 自己的「外观」设置；原文行的注音（`<ruby>/<rt>`）也跟随官方 —— 官方开着就渲染注音，官方关着就一个字符都不变。

### 学习面板（常驻，两种挂载形态）

![学习面板的两种挂载形态](docs/images/panel.svg)

- **watch 页**：面板插进 YouTube 自己的推荐列（`#columns #secondary` 的第一个子节点），宽度与位置由 YouTube 计算 —— 因此**不遮挡任何东西**。
- **其它页面**（首页 / 搜索页没有那一列）：退回「右侧悬浮 + 页面让位」，让位规则是实测出来的（见 `tools/probe.mjs`）；那种形态下面板会收窄页面，并在视频全屏时自动收起。
- 宽度可拖（300–760px），关闭后记住宽度与开启状态。
- 能力：实时双语字幕、当前句高亮 + 句内扫过填充、逐句列表点击跳转、导出中日对照 Markdown（Obsidian 友好）/ 双语 SRT / 复制到剪贴板。

### 字幕句内断句

按日语「文节」切开原文行，在每节之间画一个分隔符，便于跟读与朗读停顿：

```text
私は|昨日|図書館で|日本語の|本を|借りました。|
先生が|ゆっくり|説明してくれたので、|よく|分かりました。|
```

分隔符挂在空 `span` 的 CSS `::after` 上 —— **一个字符都不进文本流**（不改写、不删减、不加空格），所以官方的点词查词、拖拽选词、以及我们的轨道记录与导出都不受影响。

切分口径（`05-ja-segment.js`，用浏览器内建的 `Intl.Segmenter` / ICU 分词，零依赖）：

| 规则 | 例子 |
| --- | --- |
| 名词 / 代词 / 数词与其后的助词不分家 | `私は\|`、`学校へ\|`、`三冊の\|本を\|` |
| 动词与其助动词 / 否定 / 时态 / 敬体 / 补助动词连成整体 | `読んでいます\|`、`見せてもらいました\|`、`行かなかった\|` |
| 形容词 / 形容动词与其活用合并 | `美しかった\|`、`静かではありません\|` |
| 连体修饰语与被修饰名词之间切开 | `昨日\|買った\|本を\|読む\|` |
| 副词 / 接续词 / 感叹词单独成节 | `とても\|`、`ゆっくり\|`、`しかし、\|` |
| 固定语法保持整体 | `～ことが\|できる\|`、`～ために\|`、`～わけではない\|` |
| 数词＋量词 / 日期 / 外来语复合词不拆 | `三冊\|`、`2026年に\|`、`10月3日に\|`、`コンピューターゲーム\|` |
| 复合名词 / 专有名词连着写 | `日本語学校で\|`、`東京都に\|`、`会社員として\|` |
| 标点原样保留：`。！？` 后成节，逗号只跟着上一节 | `読んだ、\|`、`分かりました。\|` |

**能力边界**（如实登记，都是刻意的取舍）：

- 复合词靠启发式 + 两张表，不是词典：表外的量词（`1棟` 的 棟）、`勉強 + 時間` 这类不在表里的复合词仍会切开。
- 相邻的两个外来语词会被连写成一节（`アメリカ カナダ` 这种并列）。
- 「1か月」写作平假名时 ICU 会切成 `1 / か / 月`，只有 `1ヶ月` / `1カ月` 能正确合并。
- 补助动词（ある / いる / くる…）一律黏回前一节，所以「5分あるいて」会被连成一节。
- 判不准时一律偏向「另起一节」：宁可多切一刀，也不把两个自立词黏死。
- 整句只有一个文节时（`読んでいます。`）不画分隔符 —— 没有内部停顿可标。

### 挂在官方设置面板里

上面这些开关出现在 **Linglass 自己的设置面板**（`Linglass Mod` 分组）里，与「字幕样式」「同步模式」那些行同款观感，而不是页面上的外挂按钮。

## 环境要求

- Node.js 18+（用到 `node:test` 与全局 `fetch`）
- macOS（`make vendor-update` 依赖系统的 `unzip`）
- Arc 或任意 Chromium 116+ 浏览器（桌面字幕浮窗需要 `documentPictureInPicture`）

## 起步

```bash
make vendor-update   # 从 Chrome 商店下载官方基线到 vendor/，然后构建
make open            # 打开浏览器扩展管理页
```

在 `arc://extensions`（或 `chrome://extensions`）里打开开发者模式，点「加载已解压的扩展程序」，选本项目的 `dist/` 目录。

> `vendor/` 不在版本控制里 —— 那是 Linglass 的专有代码，本仓库不重新分发它。第一次使用必须先跑 `make vendor-update`。

日常开发用 `make dev`：改完源码自动重建，并让扩展自动重载，不用手点刷新按钮。

## 日常命令

| 命令 | 作用 |
| --- | --- |
| `make help` | 列出全部命令 |
| `make build` | 构建 `dist/`（正式版） |
| `make dev` | 监听源码，自动重建并让扩展自动重载 |
| `make test` | 跑契约测试与逻辑冒烟测试 |
| `make check` | 自检 `dist/` 是否已正确注入 mod 脚本 |
| `make probe` | 开一个带扩展的浏览器做实测（弹窗，跑完保留窗口） |
| `make open` | 打开扩展管理页（Arc） |
| `make vendor-update` | 从 Chrome 商店拉取官方最新版作为基线，并重新构建 |
| `make vendor-from FROM=~/x.crx` | 从本地 crx / zip / 解压目录导入基线 |
| `make clean` | 删除 `dist/` |

想指定视频做实测，直接用探针脚本：

```bash
node tools/probe.mjs --headed --url=<视频地址>     # 也可 --keep / --wait=40
```

## 工作原理

![构建流程](docs/images/architecture.svg)

**只读基线 + 增量叠加。** 官方扩展的打包产物放在 `vendor/` 下，一个字节都不改；我们所有的代码都在 `src/mod/`，构建时叠加到 `dist/`。好处：

- 官方发新版时只需换 `vendor/` 目录（一条命令），`src/mod/` 原样可用；
- `git diff` 里永远不会出现官方代码，一眼能分清哪些是我们写的（`vendor/` 与 `dist/` 都在 `.gitignore` 里）。

构建脚本会顺着官方产物**动态校验**我们依赖的 DOM 契约，官方改版时在构建阶段就告警，而不是等你打开视频发现「字幕不动了」。写出去的 `manifest.json` 还会做一次注入自检（顺序是否如预期、Service Worker 模块有没有被误当内容脚本）。

模块之间不传消息，直接共享全局量：

![src/mod 的模块依赖与注入顺序](docs/images/module-map.svg)

## 目录结构

```text
linglass-Pro/
├── AGENTS.md               本仓库的 AI 行为约束（改代码前先读）
├── Makefile                门禁与日常命令
├── build.mjs               构建脚本（契约校验 + 叠加 + 注入自检）
├── README.md
├── docs/
│   ├── images/             README 的配图（手写 SVG，零依赖）
│   └── plans/NNN-*.md      一个需求一份 PLAN，做完留档
├── src/mod/                我们的全部代码（见下一节）
├── tools/
│   ├── dev.mjs             监听 + 自动重建 + 通过 SW 触发扩展重载
│   ├── import-vendor.mjs   从商店 / 本地导入官方基线
│   ├── probe.mjs           CDP 探针：在真实浏览器里读 Linglass 的内部数据
│   └── test/               契约 contract.test.mjs + 冒烟 smoke.test.mjs
│                           + 断句规则 ja-segment.test.mjs
├── vendor/                 官方基线（只读，不进版本控制）
└── dist/                   构建产物（可加载的完整扩展，不进版本控制）
```

`dist/` 的版本号沿用官方的 major / minor，patch 固定为 `900`（例如基线 `1.12.3` → 产物 `1.12.900`），避免和商店更新撞号。

## `src/mod/` 的文件名约定

数字前缀决定注入顺序。同一扩展的所有内容脚本共享一个 isolated world，因此各模块直接通过 `globalThis.__llgMod*` 互相取用，不走消息传递。

| 文件名 | 作用 |
| --- | --- |
| `00-shared.js` | 共享设施：Linglass 风格的控制栏按钮工厂、功能注册表、僵尸 DOM 清理 |
| `05-ja-segment.js` | 纯函数：把一句日文切成「文节」，给出断句位置（ICU 分词 + 助词/活用/量词/复合词判据，可在 Node 里直接测） |
| `10-subtitle-track.js` | 字幕轨道记录器：只读官方 Shadow DOM 采样，并用官方缓存的整条原文轨当骨架 |
| `15-ja-break.js` | 字幕句内断句（在 Linglass 的原文字幕行上画分隔符） |
| `30-desktop-subtitles.js` | 桌面字幕浮窗（系统级画中画 + 歌词式进度 + 播放控制栏） |
| `40-study-panel.js` | 学习面板（实时字幕、逐句跳转、导出 Markdown / SRT） |
| `50-settings-panel.js` | 把我们的功能挂进 Linglass 自己的设置面板 |
| `dev-reload.dev.js` | 仅在 `make dev` 时注入：唤醒 service worker 检查新构建 |
| `dev-reload.sw.dev.js` | 仅在 `make dev` 时挂到官方 service worker 上（内容脚本没有 `chrome.runtime.reload`） |

## 验证方式

`make test`（`node --test tools/test/*.test.mjs`，零依赖）包含两层，当前 **85 例全绿**：

```text
$ make test
# tests 85
# pass 85
# fail 0
```

- **契约测试**（`contract.test.mjs`）—— 断言我们对官方产物与 YouTube 平台的所有依赖仍然成立（DOM class、shadowRoot 模式、点击处理器的短路行为、面板的裁剪机制）。它从源码里提取我们实际用到的选择器，而不是读一份手写清单；新增对官方 DOM 的依赖必须登记进来。
- **冒烟测试**（`smoke.test.mjs`）—— 用 `node:vm` 开沙箱、把 `document` / `chrome` / `MutationObserver` 换成桩件，把 `src/mod/*.js` 原封不动跑起来，覆盖时间轴推导、去重、暂停保护、注音与断句共存、导出格式、常驻语义等。
- **断句规则测试**（`ja-segment.test.mjs`）—— 纯函数模块单独一个文件，喂空沙箱直接驱动 `cut()`，逐条对齐上面那张切分口径表；除具体切分外还断言一条与实现无关的不变量：切点严格升序且拼回去等于原文。

浏览器内的视觉与交互行为（面板滑入、浮窗是否真的留在桌面、MutationObserver 的真实时序）**Node 测不了**，属于人工确认范围；`make probe`（CDP 驱动真实浏览器）可以半自动地跑一部分。

## 已知限制

- 目前**只支持 YouTube**。
- **整条轨只有原文**：句子与时间戳来自官方自己缓存的那份原文轨（`10-subtitle-track.js` 的「骨架」一节，只读 `chrome.storage.local`），所以侧栏一打开就是整条；但**译文只可能来自实际播放** —— 官方按块懒翻译、不落盘整条译文轨，所以没看过的句子译文是空的（面板副标题会显示「译文 x/N」）。缓存被 TTL（24h / 最多 50 条）清掉后会自动退回「只记录播放过的句子」。
- **注音只在当前这一句**：官方缓存里本来就不含 `<rt>`，所以浮窗能跟随官方显示注音，而面板逐句列表与导出的 Markdown / SRT 始终是不含注音的纯文本。
- 面板在**播放页**寄生进 YouTube 的推荐列，宽度交给 YouTube 自己算，所以不遮挡任何东西；**其它页面**（首页 / 搜索页没有那一列）退回「右侧悬浮 + 页面让位」，那种形态下面板会收窄页面、并在视频全屏时自动收起。
- 句级时间戳的精度取决于 MutationObserver 的触发时刻（就是字幕切换那一瞬）；官方不暴露内部 cue 时间轴，**词级时间戳拿不到**，词级进度只能用句内线性插值近似。
- 运行的是官方商店下发的产物，所以桌面字幕浮窗依赖浏览器的 `documentPictureInPicture`（Chromium 116+，Arc 可用）。

## 开发约定

- **改代码前先读 [`AGENTS.md`](AGENTS.md)**：本仓库要求「一个需求 = 一个 PLAN」，PLAN 必须声明修改范围，越界要停下报告；`vendor/` 与 `dist/` 只读；Bug Fix 必须带回归测试。
- 需求与设计留档在 [`docs/plans/`](docs/plans)，编号连续递增。
- 提交前跑门禁：碰了 `src/mod/**` 就 `make build` + `make test` + `make check`；提交前用 `git diff --stat` 核对改动量级是否与 PLAN 相符。
- 全仓库**零第三方依赖**（`node:test` / `node:vm` / 原生 `fetch` / 手写 CDP WebSocket），也不打算为此开例外。
