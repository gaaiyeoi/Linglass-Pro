# 020 文节切分规则对齐「学习用断句符」需求

> 状态：**已完成**（Node 侧门禁全绿；浏览器内的分隔符观感未验证，见文末）

## 需求

用户给出一份完整的断句规范（10 条基本规则 + 输出要求 + 示例），要求按它优化现有断句规则，
并把结论同步进 README。规范要点：

1. 每个**文节**末尾加 `|`；除插入 `|` 外不得改写 / 删减 / 纠正原文，不加空格与注释。
2. 名词 / 代词 / 数词与其后的助词合并（`私は|`、`学校へ|`、`三冊の|本を|`）。
3. 动词与其后的助动词 / 否定 / 时态 / 敬体 / 接续 / 补助动词合并，不从中间切开
   （`読んでいます|`、`行かなかった|`、`見せてもらいました|`、`勉強してみたい|`）。
4. 形容词 / 形容动词与其活用、附属成分合并（`美しかった|`、`静かではありません|`）。
5. 连体修饰语与被修饰名词之间切开（`昨日|買った|本を|読む|`）。
6. 副词 / 接续词 / 感叹词单独成文节（`とても|`、`しかし|`、`はい|`）。
7. 形式名词与固定语法尽量保持自然整体（`～ことが|できる|`、`～ために|`、`～ように|`、
   `～わけではない|`、`～なければならない|`）。
8. 复合名词 / 专有名词 / 日期 / 数词＋量词 / 外来语复合词不可拆开
   （`日本語学校|`、`東京都|`、`三人|`、`2026年|`、`コンピューターゲーム|`）。
9. 引号 / 括号内照此切分；标点原样保留；`。！？` 后加 `|`；`、` 后是否加 `|`
   取决于其前面是否恰好是文节末尾 —— 不要只因逗号而强行切分。
10. 禁止在单词内部、汉字与其读音假名之间、助词与其前面的词之间、动词词干与活用 /
    助动词之间、固定搭配内部插入 `|`。

**示例（当作验收口径）**

```text
私は昨日図書館で日本語の本を借りました。
→ 私は|昨日|図書館で|日本語の|本を|借りました。|

先生がゆっくり説明してくれたので、よく分かりました。
→ 先生が|ゆっくり|説明してくれたので、|よく|分かりました。|
```

## 根因（现状与规范的具体差距）

用 `/tmp` 下的探针把 ICU 分词与现有 `cut()` 逐句对照（`Intl.Segmenter` + 现实现），
现状**已符合**的：`私は|昨日|図書館で|日本語の|本を|借りました。|`、
`先生が|ゆっくり|説明してくれたので、|よく|分かりました。|`、`昨日|買った|本を|読む|`、
`読んでいます` / `行かなかった` / `勉強してみたい` 不切、`とても|面白かった。|`、
`静かではありません` 不切、`ことが|できる|`、`～ように`、`～なければならない`。

**不符合**的 6 处（都有实测输出，见「完成情况」）：

| # | 现状输出 | 规范要求 | 根因 |
|---|---|---|---|
| ① | `三\|冊の\|本を\|` | `三冊の\|本を\|` | ICU 把「数词 + 助数词」切成两段，而 `shouldAttach` 对非假名片段一律另起一节，没有「数词吸住量词」这条 |
| ② | `5\|時に\|` / `2026\|年に\|` | `5時に\|` / `2026年に\|` | 同上（日期与「数词＋时间单位」） |
| ③ | `見せても\|らいました。\|` | `見せてもらいました。\|` | `も` 是副助词（在 CASE 表里），黏上去之后 `lastKind='case'`，后面 `ら` 走「格助词后的假名」分支时 `cur.pieces < 2` 为假 → 另起一节。可 `も` 在这里是**谓语链内部的副助词**，不是短语末尾的格助词 |
| ④ | `日本語\|学校で\|` | `日本語学校で\|` | 相邻的两个汉字词各自另起一节，没有「复合名词 / 接尾辞」这条 |
| ⑤ | `東京\|都に\|` | `東京都に\|` | 同上（`都` 是接尾辞） |
| ⑥ | `コンピューター\|ゲームで\|` | `コンピューターゲームで\|` | 外来语复合词被切成两段，没有「片假名连写」这条 |

另外两处**语义**与规范不符（输出恰好一致，但机制不对）：

- `、` 被放进了「硬停顿」集合 —— 逗号会**强行**让下一个片段另起一节。规范 9 要求
  「不要只因逗号而强行切分」。
- 格助词后跟**单字**助词时一刀切禁止回黏，本意是挡 `花を + か(いました)`，
  但也把 `学校に + は` 挡掉了（`には` 被拆成 `学校に|は|`）。

## 做什么

在 `src/mod/05-ja-segment.js` 内按规范补 5 条判据，并修正 2 处机制：

1. **数词 + 助数词 / 时间单位**：当前节是纯数词、且下一片段以助数词开头、其余部分是
   助词假名尾巴（或空）时并进当前节。`三冊`・`5時に`・`2026年に`・`3ヶ月`。
2. **片假名连写**：当前节是纯片假名、下一片段也是纯片假名时并进当前节。
   `コンピューターゲーム`。
3. **汉字复合词 / 接尾辞**：当前节是**单个**纯汉字词、下一片段恰好是后缀名词
   （`学校`・`都`・`駅`・`会社`・`的`・`化`…）时并进当前节。`日本語学校`・`東京都`。
   用一张 `NOUN_BREAK`（`昨日`・`今日`・`毎日`・`最近`・`私`・`本当`…）挡住
   `昨日|学校で|` 这种「时间名词 + 普通名词」的误合并。
4. **谓语链里的副助词**：给文节记一个 `sawAux`（黏过助动词 / 活用尾），
   格助词之后的假名片段在 `sawAux` 为真时允许回黏 —— 修 `見せても + ら`。
   没有 `sawAux` 的（`ここで + たべられます`、`花を + かいました`）行为不变。
5. **提示助词 `は` / `も` 可以跟在格助词后面**：`学校に|は|` → `学校には|`。
   其余单字助词（`か`・`た`）仍禁止回黏，既有用例不会被打红。
6. **副词 / 接续词 / 感叹词单独成文节**：把 `STANDALONE` 从「指示词 + 形式名词 + 十几个
   高频词」扩到覆盖规范第 6 条的常用词（`ゆっくり`・`しっかり`・`はっきり`・`そして`・
   `しかし`・`それから`・`たぶん`・`きっと`…）。不加这些词时它们靠「格助词后的假名」的
   副作用偶然成节，加上之后是**规则**保证。
7. **逗号不再强行断句**：`、`・`，`・`,` 从 `HARD_STOP` 移到 `SOFT_STOP` —— 逗号照旧
   黏在上一节末尾（所以 `|` 仍落在逗号之后，与示例一致），但不再**额外**制造断点。
   `。！？…` 等仍为硬停顿。
8. **形式名词 + 否定 / 断定**：`では`・`じゃ` 收进 `LOOSE`，于是 `わけ + では + ない`
   自然连成 `わけではない`（规范第 7 条）。

外加：**扩充模块头部注释**，把 10 条规则与「哪条由哪段代码负责、哪条做不到」写清楚；
README 的「字幕句内断句」一节同步这些规则与刻意不做的事。

## 不做什么

- **不换分词器**：仍然用 `Intl.Segmenter`（ICU），不引入任何依赖或词典文件。
  词典型分词（kuromoji）能解决下面「做不到」的部分，但要拖十几 MB 字典，对内容脚本不成比例。
- **不改 `cut()` 的对外接口**：仍是「返回各文节结束处的字符下标，整句只有一节时返回空数组」。
  单文节行（`読んでいます。`）**不画末尾分隔符** —— 这是既有约定，规范里的
  「每个文节末尾加 `|`」在渲染上只在文节之间可见；面板 / 浮窗 / 导出的纯文本都不受影响。
- 不动 `15-ja-break.js`（分隔符的绘制方式）、`30-desktop-subtitles.js`、`10-subtitle-track.js`、
  `40-study-panel.js`、`50-settings-panel.js`、`00-shared.js`。
- **不动** `tools/test/smoke.test.mjs`：该文件此刻正被**另一个会话**改动（+581 行未提交），
  往里加用例会把别人的改动卷进本提交（AGENTS.md §4「一个 PLAN = 一个提交」）。
  本 PLAN 的用例落在**新文件** `tools/test/ja-segment.test.mjs`（`make test` 的
  `tools/test/*.test.mjs` 通配符会带上它）。既有用例一条都不改、不删。
- 不碰 `vendor/`、`dist/`、`build.mjs`、`Makefile`、`AGENTS.md`。

## 实现方案

1. 常量：`HARD_STOP` 拆成 `FORCE_STOP` + `SOFT_STOP`；新增 `AFTER_CASE_OK`（`は`/`も`）、
   `KATAKANA_ONLY`、`NUMERAL`、`COUNTER_HEADS`、`COUNTER_TAIL`（助词假名尾巴）、
   `COMPOUND_TAIL`（后缀名词）、`NOUN_BREAK`（不许被后缀吸走的自立名词）；
   `STANDALONE` 扩容；`LOOSE` 增 `では` / `じゃ`。
2. 文节状态加 4 个标记：`sawAux`（黏过助动词）、`pureNumeral`、`pureKanji`、
   `pureKatakana`、`first`（首片段原文，用于查 `NOUN_BREAK`）+ `softStop`。
3. `shouldAttach` 的判定顺序（新判据在 CASE/LOOSE 之前，避免被助词分支提前吃掉）：
   opener → STANDALONE → softStop → 数词＋量词 → 片假名连写 → 汉字复合词 → CASE/LOOSE
   → 假名尾巴（`case` 分支加 `sawAux`）→ …
4. `newSection` / 附加分支同步维护上述标记。
5. 用例文件 `tools/test/ja-segment.test.mjs`：直接 `node:vm` 加载
   `src/mod/05-ja-segment.js`（纯函数，不需要 DOM 桩件），断言用
   `sectionsOf(cut, text)` 把切点还原成节数组：
   - 规范里两个示例（逐字对齐）
   - 规则 8 的五个词（`日本語学校`・`東京都`・`三人`・`2026年`・`コンピューターゲーム`）
   - 规则 3 / 4 的六个动词、形容词（`見せてもらいました` 是本次的回归点：先写红）
   - 规则 7 的固定语法（`わけではない`・`ために`・`ように`・`なければならない`）
   - 规则 6 的副词 / 接续词
   - 规则 9：`。` 后成节、逗号只跟着上一节
   - `学校には`（规则 10 的「助词与其前面的词之间不切」）
   - 不变量：切点严格升序、拼回去等于原文；非日语行放过
