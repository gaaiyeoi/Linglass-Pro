# 009 字幕进度：拖进度条不再污染估计，画面与时间轴不一致时不画假进度

> 状态：**已实现，未提交**（`make test` / `make build` / `make check` 全绿；浏览器内行为待人工确认）

## 需求

用户反馈「浮窗那个进度不是很准」。本轮把**能修的**修掉，并把**修不了的**（官方不给 cue
时间轴）写清楚。

## 根因

### 1. 拖进度条会被当成「这句播了这么久」（真 bug）

`10-subtitle-track.js` 的 `extendActive()`：

```js
if (lastTickTime != null && t - lastTickTime < 0.05) return;  // 只防了暂停
lastTickTime = t;
active.end = t;
```

`active.end` 的语义是「这句显示到哪一刻」（SRT 导出要用），所以它跟着播放往前推是对的。
但它同时是 `estimatedSeconds()` 的**时长样本来源**：用户在句中往前拖 60 秒，
这一句的 `end` 就跳到 60 秒之后，样本里于是多了一条「一句 60 秒」的记录。
中位数被这种超长样本抬高之后，**所有**活跃句的进度分母都偏大 —— 表现就是
「进度条走不满 / 走得比字幕慢」，而且是**持续**的偏差，不是一次性的 glitch。

### 2. 起步晚或跳转后，时间轴落后于画面 → 假的满格

`indexAt(t)` 取的是「最后一个 `start <= t` 的句子」。扩展加载晚（用户先看了 5 分钟）、
或者用户往前拖到还没记录过的区间时，它返回的是一个**已经播完**的旧句，
分母也就早过了 → `getProgress()` 被 `Math.min(1, …)` 夹到 **100%**，
一直顶到下一次字幕切换把新句记进轨道才恢复。这时候画面上的句子跟轨道里的句子根本不是同一句，
进度条却给出一个确定的「100%」，比不画更糟。

### 3. 活跃句的分母只能估（信息上限，修不了）

官方不暴露 cue 时间轴：`.linglass-word` 上的 `data-start` / `data-end` 是**字符偏移**
（`promoCards-*.js` 的 `createWordSpan`：`s.dataset.start = String(e.s)`，`e.s` 是
`Array.from(text)` 的下标），不是时间戳。所以正在播的那一句的真实结束时间**无从得知**，
只能用已定稿句子的中位数估（`estimatedSeconds()`，首句无样本时 6s）。
长句中段会提前满格 —— 这是信息缺失，不是实现 bug，如实登记。

## 做什么

- **跳转不再进时长样本**：`extendActive()` 里把「采样间隔」分成三档 ——
  `Δt < 0.05` 视为暂停（保持不动）、`Δt ≤ JUMP_SECONDS(2.5)` 视为连续播放（照旧推进
  `end`）、**超过就只更新采样点、不推进 `end`**（跨过的那一段不是这句在播）。
  2.5s 这个值给「漏掉一拍」留余量：真实采样间隔由逐词高亮的 DOM 变更 + 1s 心跳驱动，
  通常远小于 1s，而拖进度条至少是几秒起（既有用例里那种「一次 tick 前进 2s」的写法
  仍然算连续）。
- **估计样本剔除不可能的超长句**：`estimatedSeconds()` 跳过 `end - start > MAX_CUE_SECONDS(20)`
  的句子 —— 一条字幕极少超过 20 秒，超出几乎只可能来自拖进度条。
- **画面与时间轴不一致时不画**：`getProgress()` 先比对「画面上的原文」与「时间轴里那句的
  原文」；不一致就返回 `0`，即**宁可空着也不画假的满格**。画面没有字幕（空档/过渡）时不判 ——
  那只是切换的瞬间，不代表时间轴错了。
- 补回归测试：拖进度条后 `end` 不被改写、超长句不进样本、跨句不一致时进度为 0。

## 不做什么

- 不去猜活跃句的真实时长（官方不给时间轴，猜不出来）。
- 不把估计时长从「全片中位数」改成「最近 N 句的局部中位数」：那是没有测量的调参，
  本轮不改。等有实测数据（例如同一视频里估计误差的分布）再说。
- 不改 `cue.end` 的既有语义（SRT 导出拿它当「这句显示到哪一刻」），也不改导出格式。
- 不动浮窗的进度条外观（那是 PLAN 008 的范围）。
- 不改 `readLines()` / `snapshot()` / 落盘格式。

## 实现方案

1. `10-subtitle-track.js`：
   - 新增常量 `JUMP_SECONDS = 1.5`、`MAX_CUE_SECONDS = 20`（各自写明为什么是这个值）；
   - `extendActive()` 按三档处理采样间隔；
   - `estimatedSeconds()` 过滤超长样本；
   - `getProgress()` 增加「画面与时间轴一致」的前置判断（新增内部函数 `onTimeline(primary)`）。
2. `tools/test/smoke.test.mjs`：
   - 回归 1：`h.currentTime = 10` 建句 → 心跳推进到 12 → 跳到 90 → 断言 `end` 仍是 12；
   - 回归 2：造一条被跳转污染的超长句 + 两条正常句，断言估计时长只取正常句；
   - 回归 3：造两句，把播放位置挪到第一句、但画面仍显示第二句 → 断言进度为 0；
     再把画面同步成第一句 → 断言进度恢复成正常值；
   - 既有一条用例（「有下一句时，进度分母用下一句的起点」）里，回退播放位置时
     **没有**同步画面文本，与新语义冲突：改成回退后同时把画面切回那句
     （现实里 YouTube 会重渲染字幕，这才是真实路径），并在注释里写明为什么改。
